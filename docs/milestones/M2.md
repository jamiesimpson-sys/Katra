# M2 — Module loader and question banks

## What's in it

- **Module format** (`backend/katra/engine/modules/`): a strict Pydantic schema (unknown keys rejected), a loader for `*.yaml`, `*.yml` and `*.json`, and a registry. The authoring guide is [`docs/MODULES.md`](../MODULES.md).
- **Clear errors:** invalid modules stop startup with messages that name the file and field, for example `resignation.yaml: sections.0.questions.0.priorty: Extra inputs are not permitted`. Every bad file is reported at once.
- **Checks when a module loads:**
  - section, question, document-type and output ids are unique;
  - questions only refer to document types that are defined;
  - coverage overrides only name sections that exist;
  - the file name matches the id;
  - report templates render in a sandbox with every allowed placeholder, and an unknown placeholder fails.
- **`modules/diligence_ready.yaml`:** 48 questions, 6 each across Customers, Pricing, Suppliers, Staff, Operations, Financials, Legal and Risks. Each has a priority, follow-up hints and related document types. The module also defines 13 document types, coverage rules (stricter for Legal) and a diligence report template.
- **`modules/resignation.yaml`:** a minimal key-person handover module (4 sections, 6 questions) proving the format generalises.
- **Version pinning:** each project stores a snapshot of its module when it is created, so editing a module file never changes a project already in progress. Projects created before M2 fall back to the current file.
- **API:**
  - `GET /api/modules` and `GET /api/modules/{id}` (staff only);
  - `GET /api/projects/{id}/module` (any project member);
  - creating a project with an unknown module is rejected.
- **UI:** a module picker in New project, showing the description and question count, and a read-only **Question bank** page for admins and owners.

## Tests

95 backend tests in total (35 new):
- Every shipped module loads, its ids are unique and its templates render.
- The `diligence_ready` question bank has the expected shape.
- 13 kinds of malformed module, each failing with the file and field named.
- The registry reports every bad file at once, and JSON modules work.
- **Adding a module by dropping in a file**, then using it through the API.
- **Version pinning** across a module edit.
- The module catalogue is staff-only.
- A guard test fails if any module or question id appears in application code.

## Carried forward

- Coverage rules are validated now, but computed in M6.
- Follow-up hints and document types feed the interviewer in M4. The question bank page shows document types but not the hints, which are guidance for the interviewer.
