# M1 — Skeleton, Compose, auth and roles, schema

## What's in it

- **Stack:** `make up` starts `web` (Caddy, HTTPS and the SPA), `api` (FastAPI), `worker` and `db` (Postgres 16 + pgvector). On first run it creates `.env` with random secrets and an admin login.
- **Schema:** the full data model from PLAN §5 as one Alembic migration (`backend/katra/db/migrations`). It includes HNSW vector indexes and a trigger that makes `audit_log` append-only (UPDATE, DELETE and TRUNCATE are rejected).
- **Auth:**
  - Argon2id passwords.
  - Session tokens stored hashed, in an httpOnly, Secure, SameSite=Lax cookie.
  - A double-submit CSRF token on every mutating request.
  - Login rate limiting, with the same response whether or not an email exists.
- **Roles:** per-project `admin` / `owner` / `viewer`, plus `is_staff` for creating projects.
  - Every `/api/projects/{project_id}/…` route goes through `require_project_role(...)`.
  - Non-members get a 404, so they can't probe project ids.
- **Invites:** an admin creates an invite and gets a one-time link, valid for 72 hours. The invitee either sets a password or confirms their existing one. Invites can be revoked.
- **Audit:** logins (including failures), project create and view, invites created, accepted and revoked, and member removal. Admins can read the log in the UI.
- **Interfaces:** `LLMProvider`, `EmbeddingProvider` and `BlobStorage`, with deterministic fakes.
- **Job queue:** Postgres-backed, using `SKIP LOCKED`, with retries and backoff, plus a worker process.
- **Frontend:** login, accept-invite, project list and create, and a project page whose navigation depends on the role. Members, invites and the audit log work now; later pages show "arrives in M#".

## Tests (`make test`)

- **Backend (60 tests, real Postgres):**
  - Auth flows and CSRF.
  - Invite lifecycle.
  - A role × endpoint × project authorization matrix, including outsider and anonymous users.
  - A **route-inventory test** that fails if any project route lacks the RBAC guard or is missing from the matrix.
  - Audit append-only behaviour, the job queue's retry and failure handling, and a check that the models and migrations match.
- **Frontend (Vitest):** role → navigation rules.

## How to try it

```sh
make up                       # prints the URL; admin login is in .env
open https://localhost:8443   # local certificate: accept the browser warning once
```

1. Sign in as admin and create a project.
2. Go to **Members** and invite an owner and a viewer.
3. Open each invite link in a private window. Each role sees only its own pages.

## Known limitations / carried forward

- The module id is free text until M2 adds the module loader and picker.
- The login rate limiter is in-process (one API container). Use Redis if the API is scaled out.
- The database is encrypted at rest only if its volume is on encrypted storage. File blobs get application-level encryption in M3.
- Building behind a TLS-intercepting proxy needs that proxy's CA added to the Docker builds.
