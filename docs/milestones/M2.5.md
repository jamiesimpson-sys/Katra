# M2.5 — Admin data browser

A superuser-only interface at **`/admin`** for browsing every table, built with
[SQLAdmin](https://aminalaee.dev/sqladmin/) (`backend/katra/admin.py`).

## Access

- **Superusers only.** This is a new `users.is_superuser` flag. Staff (brokers) and project admins are refused, because the browser shows every project.
- **The bootstrap admin** (`KATRA_BOOTSTRAP_ADMIN_EMAIL`) is made a superuser on startup, so it works on Render without a shell.
- **Others** can be granted or revoked with `python -m katra.cli grant-superuser --email …` and `revoke-superuser`. Startup re-grants the bootstrap admin, so to change who that is, change the env var.
- **Sign-in uses the normal Katra session**, with no separate password. Superusers see an **Admin** link in the app header, and the admin's Logout ends the Katra session.

## What can be changed

| Table | Editable fields |
|---|---|
| Users | display name, active, staff (not superuser, not email) |
| Projects | name, status, retention days |
| Invites | revoked at (set a time to revoke) |
| Everything else | read-only |

- Nothing can be created, deleted or exported through the admin.
- Knowledge items are read-only, because editing an answer or its status would bypass owner verification.
- Password hashes, session and invite token hashes, encryption keys and embeddings are never shown. The auth sessions and project keys tables have no page at all.

## Audit

- Every admin page view is logged as `admin.view`, with the path.
- Every edit is logged as `admin.update`, with the changed **field names only**, never their values.

## Tests

44 new, 139 in total:
- refusal for every non-superuser role, and redirect to login when signed out;
- every table lists for a superuser;
- secrets are hidden on every page, with a per-view check that the hidden lists cover every secret column;
- read-only tables refuse create, edit and delete;
- edits to safe fields work, and attempts to set the superuser flag or email are ignored;
- page views and edits are audited;
- bootstrap promotion, the CLI, and admin logout.

## Notes

- Admin forms rely on the SameSite=Lax session cookie for protection against cross-site form posts. They don't carry the app's CSRF header.
- `/admin` has its own Content-Security-Policy, because SQLAdmin uses inline scripts.
